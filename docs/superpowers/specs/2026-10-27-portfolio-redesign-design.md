# 포트폴리오 전체 리디자인

사용자 승인: 2026-10-27. 목표는 신뢰할 수 있고 믿음직한 개발자라는 인상을 주는 포트폴리오다. Spotlight 공개 사이트의 여백, 중립색, Teal 포인트, 읽기 구조를 기반으로 대표 프로젝트와 검증 근거를 강조한다. Catalyst는 관리자 및 일부 공용 UI에 사용한다.

## 범위와 제약

- 새 브랜치 `codex/portfolio-redesign`에서 작업한다. 커밋, 푸시, 배포는 이번 요청 범위에 포함하지 않는다.
- 기존 검색, 다중 필터, 정렬, 페이지 이동, 상세 slug, 메타데이터, 조회수, 폼, 인증, 관리자 CRUD와 콘텐츠 편집 기능을 유지한다.
- Dev 및 Live 서버에는 절대로 직접 접속하지 않는다. 모든 런타임 검증은 loopback에 바인딩된 앱과 로컬 fixture API로 수행한다.
- 검증 중 브라우저와 서버의 외부 요청을 차단한다. API의 기본 URL, 공개 fallback, 조회수 증가 및 폼 전송까지 로컬로 고정한다.
- 실제 성과, 경력, 프로젝트 데이터는 만들지 않는다. fixture는 검증 데이터임을 명확히 표시한다.
- 현재 API/HTML 콘텐츠 렌더링 및 정화 처리를 유지한다. Spotlight MDX 파이프라인으로 교체하지 않는다.

## 화면과 디자인

공통: Zinc 중립색, Teal 포인트, 시스템 한글 sans 글꼴, 최대 약 1120px 콘텐츠 폭, 약 720px 글 읽기 폭. 얇은 테두리와 제한된 그림자, 12/20px 중심 모서리, 150~200ms 상태 전환. 라이트/다크 대비 및 reduced-motion 지원.

홈: 간결한 개발자 소개, 대표 프로젝트, 경험과 기술, 개발 기록, 연락 동선. 프로젝트를 글보다 먼저 크게 배치한다. 갤럭시, 장식용 그라데이션과 순차 공개 대기는 제거한다.

프로젝트: 이미지 중심 목록. 상세는 역할/기간/상태 등 실제 데이터와 본문을 읽기 쉽게 연결한다. 블로그: 담백한 제목 중심 목록과 일관된 prose 본문. 소개: 경험과 실제 기술 활용 중심. 연락: 상태가 분명한 폼. 설정: 읽기 쉬운 설명 목록. 관리자: 기존 동작을 유지하는 Catalyst 기반 셸과 일관된 폼/테이블.

## 접근 방식

Spotlight 전체 앱 교체는 현재 API와 관리자 구조를 불필요하게 바꾸므로 채택하지 않는다. Studio는 사례 소개의 시각 참고로만 사용한다. Spotlight의 검토한 실제 컴포넌트를 필요한 범위로 통합하고 현재 데이터 로직 위에 표현 계층을 교체한다. Catalyst는 선택한 실제 소스 컴포넌트를 로컬 프로젝트에 통합한다.

## 검증

기존 node:test 회귀 테스트, TypeScript, ESLint, production build를 확인한다. 추가 검증은 API 격리 실패 차단, 주요 공개/관리자 화면, 검색/필터/폼/테마/모바일 메뉴, 로딩/빈/실패 상태에 집중한다. 로컬 브라우저는 외부 요청을 거부하며 desktop/mobile 및 light/dark에서 오버플로와 조작을 확인한다.
