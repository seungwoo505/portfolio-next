## 수정 계약

1. 인증 확인의 네트워크/서버 장애에는 access/refresh 토큰을 보존한다. 확인되지 않은 관리자 콘텐츠를 보여주지 않고 오류와 재시도를 제공한다. 명시적 인증 거부와 로그아웃은 기존처럼 인증을 해제한다.
2. 이미 공개된 글의 수정은 원래 `published_at`을 보존한다. 초안의 최초 공개만 현재 시각을 쓰고, 비공개 저장의 기존 동작은 유지한다. 원래 발행 시각이 없는 공개 글에는 임의의 현재 시각을 만들지 않는다.
3. 기술 필터에 쉼표로 구분된 `technologies`도 포함한다. 기존 skills/tags 및 복수 OR 필터와 카드 표시 순서를 보존한다.
4. 프로젝트 클라이언트는 서버가 넘긴 slug를 다시 디코딩하지 않는다. `%`와 `%20` 같은 리터럴 문자열을 보존한다.
5. 공개 API의 slug/tagSlug는 URL 경로 세그먼트로 인코딩한다. 일반·한글·`%`·`#`·`?` 값을 검증한다.
6. 프로젝트 HTML이 공백이면 기존 Markdown을 표시한다. 본문이 모두 비었을 때 영구 로딩 상태를 만들지 않는다. 기존 HTML 정화 경계는 유지한다.
7. 블로그/프로젝트 조회수는 API의 성공을 확인한 뒤에만 증가한다. 업무 실패·HTTP 오류·네트워크 실패는 표시 숫자를 바꾸지 않는다.
