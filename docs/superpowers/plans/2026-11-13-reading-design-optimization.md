# 모바일 목록·홈 데이터·긴 본문 개선

승인 범위는 1) 모바일 필터 압축 2) 홈 전달 데이터 경량화 3) 긴 상세 자동목차다. 기존 codex/portfolio-redesign과 앞선 미커밋 초기표시/API/블로그 개선을 보존한다. 새 커밋·푸시는 하지 않는다.

제품 변경 전 같은 소스의 새 production build를 기준으로 삼고 .verification/reading-design-20261113/before에 저장한다. 이후 1→2→3 제품 적용 후 새 빌드로 after를 수집한다. Node TCP/DNS/fetch, Chrome HTTP/WS와 blackhole proxy를 유지해127.0.0.1 앱4318/API4319 외부를 차단한다. Dev/Live에는 접속하지 않는다.

비교 데이터는 동일한 ISOLATED_RASTER_IMAGES=1, ISOLATED_CONTENT_BENCHMARK=1 fixture다. 긴 본문, 중복 한글 제목, 편집JSON은 외부에서 가져오지 않는 합성 데이터다. 사진은 기존 로컬 JPEG를 사용한다. 긴 데이터의 바이트 절감은 운영 속도나 실제 콘텐츠 용량을 대표하지 않는다. 기본 fixture 동작은 flag가 없으면 유지한다.

1. 모바일은 검색을 항상 노출하고 정렬·태그만 접는다. 선택 수·정렬 상태를 닫힌 상태에서도 확인하며 Escape는 포커스를 토글로 돌려준다. 닫힌 컨트롤은 포커스 대상에서 제외한다. 768px 이상에서는 기존 필터 배치와 기능을 유지한다. 기존 목록 진입·FLIP·공유 이미지 전환은 그대로 둔다.
2. 홈에는 명시적 표시 DTO만 전달한다. 기존 글 요약 fallback, 프로젝트 이미지·기술 정규화, 조회수0, 날짜, 빈 데이터 fallback, 갱신을 보존한다. 불필요한 원문·편집JSON은 제외한다. 실제 서버 props와 같은 화면을 만드는지 테스트하며 HTML/RSC 크기를 전후 측정한다.
3. 정화된 실제 본문 DOM의 h2/h3가 최소3개이고 텍스트1200자 이상일 때 목차를 만든다. 짧은 본문은 기존 화면 그대로다. 모바일은 기본 접힘, 데스크톱은 기본 열림, native hash 탐색과 sticky header 여백을 사용한다. 기존 앵커는 보존하고 중복/외부 ID 충돌을 피한다. 언마운트/본문 갱신 때 정리하며 기존 sanitization 경계를 바꾸지 않는다.
4. 관련 실제 동작 RED→GREEN, 전체 unit/ESLint/TypeScript/production build, 기존 smoke57·motion5·connected13을 검증한다. 공개32화면을 전후 비교하되 의도된 모바일 필터/조건부 목차 차이와 그대로여야 하는 본문·데스크톱 목록·홈을 구분해 기록한다. 제목/본문/표/이미지/링크 내용과 스타일은 보존한다. 비교 하네스가 모바일 첫 카드 위치, 필터 접근성·기능, 목차 이동/포커스/ID 유일성을 확인한다.
5. 최종 결과와 제한을 기록하고 이번 launcher 소유 프로세스만 종료한다. Node·Next 버전과 기준 파일의 상태를 함께 보존한다.

## 최종 결과

1→2→3 적용 후 전체238단위, smoke57, motion5, connected13, 추가 브라우저10개가 통과했다. 공개32사례는20개 동일화면+12개 의도된 모바일/목차 변경으로 나누어 검증했고 최종 하드 차이는0이었다. 정화된 본문·이미지·링크·표와 기존 기능·모션을 보존했다. 사이트 모션 감소의 native 스크롤도 검토 후 보완했다.

390px 모바일에서 두 목록의 첫 카드가134px 올라왔다(프로젝트841.75→707.75px, 블로그803.36→669.36px). 데스크톱 카드 위치는 같았다. 같은 긴 합성 API 데이터를 사용해 홈 HTML188,266→41,708B, gzip 계산12,786→9,147B, 화면용 props143,551→1,537B로 줄었다. API원본198,081B는 동일했고 이는 운영 속도 측정이 아니다.

상세 방법·제약·원본·비교 예외·캡처는 .verification/reading-design-20261113/summary.md와reading-comparison.json을 참조한다. 기존 미커밋 변경을 보존했고 이번 변경도 미커밋이다. Dev/Live 접속 없이 외부 차단 로컬 환경에서 검증했으며 검증 서버 종료는cleanup.json으로 확인한다.
