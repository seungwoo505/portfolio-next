# 사전 불러오기와 프로젝트 요약 검토

2026-11-13. 기존 기능·디자인·애니메이션을 유지하고 외부 통신을 차단한 로컬 fixture에서 검토했다. Dev/Live 접속, 실제 글·DB 수정, 배포는 하지 않았다.

## 선택적 사전 불러오기

동일한 production 빌드에서 프로젝트·블로그 상세는 cold/auto/full 각각 3회, 소개·연락처는 cold/full 각각 3회로 총 30회 측정했다. RSC 응답에 같은 350ms 지연을 주고 클릭 직전부터 대상 경로·제목 표시까지 측정했다. 전체 방문자의 LCP나 운영 성능을 나타내는 수치는 아니다.

| 경로 | 사전 준비 없음 중앙값 | auto | full |
|---|---:|---:|---:|
| 프로젝트 상세 | 432.0ms | 409.4ms | 393.1ms |
| 블로그 상세 | 422.1ms | 409.8ms | 394.1ms |
| 소개 | 445.2ms | 해당 없음 | 388.9ms |
| 연락처 | 432.0ms | 해당 없음 | 383.3ms |

이번 조건에서는 사전 요청 뒤에도 클릭 시 RSC 요청이 남았다. 약 28~56ms의 이점과 추가 요청 비용을 고려해 제품 전면 적용은 보류했다. 설치된 Next 16.2.9의 `window.next.router` 진단 bridge로 수행한 예비 실험이며, 이 bridge는 실제 앱 코드에 사용하지 않는다.

사전 준비 중 URL과 fixture 조회수는 변하지 않았다. 실제 상세 진입에서만 조회수 POST 1회와 +1을 확인했고 정적 메뉴 이동에는 POST가 없었다. 외부 요청과 미처리 브라우저 오류는 0이었다. 향후 제품 반영 시에는 공개 링크 hover/focus, 데이터 절약·저속 연결 정책, 중복 억제와 기존 전환을 별도로 검증해야 한다.

## 프로젝트 핵심 요약 시안

별도 역할·문제·해결·결과 필드가 현재 Project 타입과 관리자 폼에 없어 공통 작성 틀과 배치 시안만 만들었다. 사용자가 특정 글에 묶일 필요가 없다고 안내했으므로 실제 프로젝트 내용이나 확인되지 않은 성과를 채우지 않았다.

[독립 HTML 시안](../../previews/project-summary.html)은 대표 이미지 아래, 기존 소개·본문 앞에 요약을 배치한다. 넓은 화면은 4열, 모바일은 2열이다. 외부 의존성이 없는 검토용 파일이며 실제 서비스 화면이나 제품 기능이 아니다. 제품 반영 시에는 확인된 항목만 표시하고 자료가 없는 항목은 숨기는 방식을 권장한다.

상세 원본은 Git에서 제외한 `.verification/prefetch-summary-20261113/`에 보존했다. `report.json`은 상세 18회, `static.json`은 정적 이동 12회 측정이다. 두 probe 스크립트는 진단용이며 제품 코드가 아니다. 데스크톱·모바일 시안 캡처와 `cleanup.json`도 같은 위치에 있다.

## 커밋 정리

초기 표시·읽기 화면 개선 문서의 ‘미커밋’ 표기는 당시 검증 시점의 기록이다. 이후 사용자가 Markdown을 포함한 현재 작업의 목적별 커밋을 요청해 구현, 테스트, 비교 도구, 문서와 HTML 시안을 함께 정리한다. 사전 불러오기와 프로젝트 요약은 검토·시안 상태를 유지한다. 푸시·배포는 이번 요청 범위에 포함하지 않는다.
