# 초기 표시와 공개 요청 최적화

2026-11-13, 기준650e89f. 승인 범위는 홈 SSR 초기 표시 → 공개 GET 중복 및 푸터 순차 요청 제거 → 블로그 태그 대기 분리다. 기존 기능·디자인·모션을 유지하며 현재 브랜치에서 진행한다. 새 커밋·푸시 없이 변경을 남긴다.

Dev/Live에 접속하지 않는다. 기존 TCP/DNS/fetch guard와 Chrome proxy/HTTP/WebSocket guard, 합성 API4319/앱4318, 동일한 로컬 JPEG를 사용한다. 기존 performance 기록은 보존하고 이번 결과를 .verification/loading-optimization-20261113 아래에 별도 저장한다.

1. 변경 전 production 빌드와 공개32화면을 캡처한다. home JavaScript 비활성 상태, JS300ms 지연에서 h1 표시, 목록100ms/태그500ms에서 블로그 카드 표시, 설정500ms/프로필300ms에서 실제 요청 횟수·시작 간격·완료를 프로필별5회 측정한다.
2. 홈은 서버에서 받은 목록이 있으면 최초 렌더부터 본문을 표시한다. 데이터가 없거나 로딩 중인 경우의 기존 fallback 및 조회수 갱신을 보존한다. 실제 React 서버 렌더 회귀 RED/GREEN.
3. ApiClient 인스턴스에서 같은 공개 GET의 진행 중 요청만 공유한다. 완료·실패 뒤에는 저장하지 않으며 서로 다른 쿼리·인스턴스·관리자 요청·POST는 공유하지 않는다. 쓰기 요청은 기존 진행 요청 재사용을 끊는다. 푸터 설정·프로필은 병렬로 읽되 기존 설정 우선 병합 순서는 유지한다. 태그·설정·조회수의 오래된 결과를 지속 캐시하지 않는다.
4. 블로그는 원본 글과 태그를 독립적으로 받으며 useMemo에서 태그 이름→slug 매핑을 재계산한다. 응답 순서와 태그 오류가 목록에 영향을 주지 않아야 하고 초성 검색·복수 OR 필터·정렬·페이지네이션을 유지한다. 태그 실패를 글 조회 실패로 취급하지 않는다.
5. 최종 빌드에서 동일 조건으로 재측정하고32화면의 텍스트·스타일·배치·이미지를 비교한다. 조회수만 정규화하고 rect는0.5px 허용한다. 최종 결과의 UI 차이는0이어야 한다. 기존 unit/ESLint/TypeScript 및 smoke57·motion5·connected13도 확인한다.
6. 실제 수치와 합성 환경의 한계를 기록하고 이번 소유 프로세스만 종료한다. 시각 비교의 baseline은JS가 실행된 정상 화면이며 JavaScript 미실행 홈은 의도적으로 개선된다.
